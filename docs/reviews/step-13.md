# step13: スタッフ用 Web 画面

## 1. やったこと
- `web/` に Next.js 16（TypeScript・Tailwind CSS）でスタッフ用の Web 画面を作った。スタッフはメールアドレスとパスワードでログインし、ログインしていなければログイン画面に送られる。
- 一覧画面: 全利用者の今日のポイント・目標までの進み具合（バーと %）・歩いた／家のこと／たいそう・最後の記録。記録が止まっているかもしれない人は朱色の枠と「⚠」の文字で上に並べる。
- 利用者ごとの画面: その日の時間帯の積み上げ棒・その週の 7 日の棒（目標の線と ★）・10 秒ごとの揺れの点のグラフ（しきい値の線つき）。前の日・次の日に動ける。グラフは外部のライブラリを使わず SVG で描いた。

## 2. 追加・変更したファイルと役割
| ファイル | 役割 |

| `web/next.config.ts` | 作り置きの機能（cacheComponents など）を外した（毎回最新のデータを出すため） |

| `web/src/lib/activity.ts` | ポイントへの換算（アプリと同じ数字）・日本時間の日付・記録が止まっているかの判定 |
| `web/src/lib/data.ts` | スタッフかどうかの確認と、表の読み出し（10 秒ごとの記録は 1,000 行ずつ分けて読む） |

| `web/.env.local`（コミットしない） | Supabase の URL と公開用の鍵 |

## 3. 確認したこと・確認する手順
- `npm run build`（型のチェックを含む）と `npm run lint` が通った。
- `npx next start` で起動し、`/` を開くとログイン画面（`/login`）に移動すること、ログイン画面が出ることを確かめた。
- ログインしたあとの画面は、スタッフのアカウントが無いのでまだ確かめていない。手順:
  1. `docs/SUPABASE_SETUP.md` の 3 章（匿名ログインを有効にする）と 4 章（スタッフの登録）を済ませる。
  2. `cd web` → `npm run dev` → ブラウザで http://localhost:3000 を開き、スタッフのメールアドレスとパスワードでログイン。
  3. アプリで初回設定を済ませ、スタッフ用画面の「今すぐ送る」→ 一覧にその人のカードが出る。カードを押すと利用者ごとの画面。
  4. スタッフに登録していないアカウントでログインすると「スタッフとして登録されていません」が出て、データは見えない。

## 4. 判断を保留した点
- **換算の数字が2か所にある**: ポイントへの換算・しきい値は、アプリ（Kotlin の config）と Web（`web/src/lib/activity.ts`）の両方に書いている。片方だけ変えると数字が合わなくなる。将来は Supabase の表に設定として置くなど、1か所にまとめたい。
- **しきい値の線は今の値（25mg）**: Web で線を動かして試す機能はまだ無い。どの値がよいかが分かったら、アプリの config を変えて入れ直す。
- **「記録が止まっている」の判定**: 記録するサービスが止まっていると送ってきた、または最後の記録から 60 分以上たったとき。送る間隔が 15 分なので、少し遅れて出る。
- **書体**: Web から書体を読み込まず、端末の日本語の書体を使う（大学のネットで読み込みが遅いことがあったため）。
- **npm の注意**: `npm audit` で中くらいの注意が 7 件出ている（Next.js の開発用の道具の中のもの）。公開前に確かめる。
- **利用者を消す・名前を直す機能**: Web 画面にはまだ無い（よび名はアプリから送られたものをそのまま出す）。

## 追補（2026-11-13）: 表示を業務向けに変更
開発者から「スタッフ側は簡単な日本語にする必要はなく、情報が分かりやすいことが最優先」と指示があったため変更した。
- 一覧をカードから **表** に変えた（状態・活動pt/目標・達成率・歩数・歩行pt・生活活動pt・体操・最終記録・最終受信）。上部に利用者数・目標達成人数・平均達成率・記録停止の可能性の人数を出す。並び順は「停止の可能性あり → 達成率の低い順」。
- 詳細画面に、達成率・体操・目標までの数値、時間帯別の数値の表、週の達成日数と合計歩数、10 秒ごとの記録から求めた歩行・生活活動の時間、しきい値のすぐ下で「静止」と判定された件数を足した。利用者ID・登録日時・停止の判定条件も出す。
- 言葉を業務向けにした（「家のこと」→「生活活動」、「たっせい」→「達成」、「歩いた」→「歩行」など）。アプリの利用者向けの言葉は変えていない。
- 同じ内容を `docs/SPEC_UI.md` 10章にも書いた。
