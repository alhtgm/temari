# step12: Android からの送信

## 1. やったこと
- 記録するサービスが、15 分ごと（と記録を始めたとき）に、利用者の情報・時間帯ごとの集計・体操の回数・10 秒ごとの記録を Supabase に送るようにした。端末は匿名ログインで自動でログインする。
- 送る前の 10 秒ごとの記録は待ち行列にため、ファイルにも保存する。ネットにつながらないときはため続け（約 7 日分まで）、つながったら古い順に送る。
- スタッフ・開発用画面に「最後に送った時刻・送れていない件数・失敗の理由・今すぐ送る」を出した。新しいライブラリは入れていない。

## 3. 実機で確認する手順と、期待される見た目・動き
前提: Supabase の管理画面で **匿名ログインを有効** にしておく（`docs/SUPABASE_SETUP.md` 3.1）。まだ無効だと、送信は「HTTP 422 … Anonymous sign-ins are disabled」で失敗する。

1. アプリを入れ、初回設定を済ませる（利用者IDが発行される）。
2. せってい →「スタッフ用」長押し →「データの送信」に「最後に送った時刻」が出る（記録を始めたときに1回送る）。
3. 端末を持って歩き、「今すぐ送る」→ 送れていない件数が 0 になる。
4. Supabase の管理画面 → Table Editor で `app_users`（よび名）・`block_records`（時間帯ごとの歩数）・`epochs`（10 秒ごと）に行が増えている。
5. 機内モードにして数分記録 →「今すぐ送る」→ 失敗の理由が出て、送れていない件数が増えたまま。機内モードを戻して「今すぐ送る」→ 0 になり、表に抜けなく増えている。

## 4. 判断を保留した点
- **送る間隔 15 分**: Web 画面はそのぶん遅れて新しくなる。もっと早く見たいなら短くできるが、電池と通信量が増える。
- **ログインし直しになった場合**: 端末の保存が消えるなどで匿名ログインがやり直しになると、前の利用者IDの行は前のログインのものなので、書けなくなる（403）。そのときは初回設定のやり直しで新しい利用者IDにする。めったに起きないので自動では直していない。
- **よび名と 10 秒ごとの記録を送る**: 開発者の判断で送る。実際の利用者に使ってもらう前に同意を取る（`docs/SUPABASE_SETUP.md` 6 章）。
- **大学のネット（プロキシ）**: Android 端末が大学の Wi-Fi でプロキシの設定を必要とする場合、送れないことがある。端末の Wi-Fi の設定に従う。
- **実機での確認**: 匿名ログインがまだ無効なので、本物の Supabase への送信は実機で確かめていない（単体テストは通っている）。
