# SPEC_UI.md — UI モック段階の仕様

## 1. この段階の目的
- 画面・文言・画面の流れを、モックデータで実機（タブレット）に表示して確認する。
- 計測・判別・保存・クラウドは作らない。データはすべて `FakeActivityRepository` が返す。

## 2. コンセプト
- 「何もしなくていい、開けば分かる」アプリ。記録は自動で、利用者は開いて見るだけ。
- 否定的なことを言わない。「あと少し」「よく動けました」と伝える。

## 3. 画面構成と遷移
ホームを中心にしたハブ型。タブバーは使わない。各画面はホームから1段だけ奥にあり、画面下部に常に大きな「もどる」ボタンを置く。

```
[初回設定] ようこそ → 呼び名 → 通知の許可 → 電池の設定 → 1日の目標 → ホーム
                                                            （2回目以降は直接ホーム）

ホーム ─┬─ ふりかえり（もどる→ホーム）
        ├─ ビンゴ    （もどる→ホーム）
        └─ せってい  （もどる→ホーム）
               └─ 長押し → スタッフ・開発用（もどる→せってい）
```

### 3.1 ホーム
- 上: 「◯◯さん、こんにちは」（時間帯で おはようございます／こんにちは／こんばんは）
- 中央（最も大きく）: きょうの活動ポイント（48sp 以上）と、目標までの進み具合バー
  - 未達成: 「目標まで あと ◯◯」
  - 達成: 「目標たっせい！」
- 内訳2行: 「歩いた ◯◯ポイント（約 ◯◯歩）」「家のこと ◯◯ポイント」
- ひとことメッセージ（5章のルールで1つ選ぶ）
- 記録の状態
  - 記録中: 小さく「● 記録中」
  - 停止中: 目立つ枠で「記録が止まっています」と「再開する」ボタン。モックではボタンを押すと記録中に戻る。
- 大きなボタン2つ: 「ふりかえり」「ビンゴ」
- 最下部に小さめのボタン: 「せってい」

### 3.2 ふりかえり
- 上部の切り替えボタン（大きく2つ）: 「きょう」「今週」
- きょう: 4つの時間帯の棒グラフ（時間帯の区切りは 4章）
- 今週: 月〜日の7本の棒グラフ。目標を達成した日には棒の上に印（★と「たっせい」の文字）。
- どちらも、歩いた／家のこと を積み上げ棒で色分けし、模様（家のこと側を斜線）と凡例ラベルも付ける。
- グラフの下に1行の文章: 「いちばん動いたのは ◯◯ でした」
- 下部に「もどる」

### 3.3 ビンゴ
- 3×3、1週間（月曜はじまり）で1枚。中央は最初から開いている「フリー」。
- マスは条件の短い名前を表示し、達成済みのマスは色と「✓」で示す。
- マスを押すと、条件の説明を大きな文字のダイアログで表示する（「とじる」ボタン付き）。
- 1列そろったら、お祝いの演出（大きな文字「ビンゴ！」と簡単なアニメーション）。そろった列は線で示す。
- 画面上部に「今週のビンゴ（◯月◯日〜◯月◯日）」、下部に「もどる」。
- マスの条件（モック用。判定はモックデータの値で行う）:
  | マス | 条件 |
  |---|---|
  | 朝からげんき | 朝の時間帯に活動ポイントが一定以上の日がある |
  | 目標たっせい | 目標を達成した日が1日以上 |
  | 目標たっせい×3 | 目標を達成した日が3日以上 |
  | 家のことマスター | 家のことポイントが一定以上の日がある |
  | 夜もすこし | 夜の時間帯に少しでも活動した日がある |
  | 3日つづけて記録 | 記録が3日連続で取れた |
  | よく歩いた日 | 歩いたポイントが一定以上の日がある |
  | 毎日コツコツ | 今週すべての日で活動がある（今日まで） |
  | フリー（中央） | 最初から開いている |
  「一定以上」の値は `config/` の定数にする（仮の値でよい。仮であることをコメントに書く）。

### 3.4 せってい（利用者向け）
- 文字の大きさ: 「大」「特大」の2択（大きなボタン）
- 呼び名の変更
- 1日の目標（「−」「＋」の大きなボタンで変更。キーボード入力はさせない）
- 下部に「もどる」
- 画面の一番下に目立たない文字で「スタッフ用」。**長押し（2秒）** でスタッフ・開発用画面へ。

### 3.5 スタッフ・開発用
- モックデータのシナリオ切り替え（6章）
- 現在の利用者ID、初回設定のやり直しボタン（確認ダイアログ付き）
- 記録の状態・センサー情報・データ書き出し は「準備中」と表示するだけ（後の段階で作る）
- この画面だけは文字サイズ規定（20sp）を守らなくてよい

### 3.6 初回設定
施設でスタッフが一緒に設定する前提。各画面は「つぎへ」ボタン1つ（必要なら「もどる」も）。
1. ようこそ: アプリの説明（3行以内）
2. 呼び名: 入力欄と「つぎへ」。このとき利用者ID（UUID）を自動発行して保存。ログインはない。
3. 通知の許可: Android 13 以上なら `POST_NOTIFICATIONS` を実際に要求する。断られても先に進める。
4. 電池の設定: 「電池の最適化から外す」説明と、設定画面を開くボタン（`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` を使う）。「あとで」でも進める。
5. 1日の目標: おすすめ値を表示し、「−」「＋」で調整
6. 完了: 「はじめましょう」でホームへ。以降は起動時にホームを直接表示する。

## 4. データの決まり（モック）
- 時間帯の区切り（`config/` の定数）:
  - 朝 5:00〜10:00 ／ 昼 10:00〜14:00 ／ 午後 14:00〜18:00 ／ 夜 18:00〜24:00（0〜5時は集計しない）
- 活動ポイント = 歩いたポイント + 家のことポイント。
- 歩いたポイントと歩数の換算、活動ポイントの計算式は未定。モックでは「歩数 ÷ 10 = 歩いたポイント」を仮に使い、`config/` に置く。
- 1日の目標の初期値: 600 ポイント（仮）。
- データモデル（例。必要なら調整してよいが、変えたら理由をレビュー記録に書く）:
  - `DailyActivity(date, walkPoints, lifePoints, steps, goal, blocks: List<TimeBlockActivity>)`
  - `TimeBlockActivity(block: TimeBlock, walkPoints, lifePoints)`
  - `RecordingStatus`（`Recording` / `Stopped(since)`）
  - `BingoCard(weekStart, cells: List<BingoCell>)`、`BingoCell(id, title, description, achieved)`
- `ActivityRepository` は `Flow` で値を返す（例: `todayActivity()`, `weekActivities()`, `recordingStatus()`, `bingoCard()`）。

## 5. ひとことメッセージのルール
上から順に判定し、最初に当てはまったものを表示する。文言は `strings.xml` に置く。
1. 記録が止まっている → 「記録を再開しましょう」
2. 目標を達成 → 「目標たっせい！ すばらしいです」
3. 目標の 80% 以上 → 「あと少しで目標です」
4. 今の時間帯までで一番動いた時間帯がある → 「◯◯によく動けましたね」
5. それ以外 → 「すこしずつ動いていきましょう」

## 6. モックのシナリオ
スタッフ・開発用画面から切り替えられ、切り替えるとすべての画面に即座に反映される。
| シナリオ | 内容 |
|---|---|
| ふつうの日（初期値） | 目標の 70% 程度。朝と午後に山 |
| よく動いた日 | 目標を超えている。今週の達成日が多く、ビンゴが1列そろう |
| あまり動けなかった日 | 目標の 20% 程度 |
| 記録が止まった | 昼から記録停止中 |
| はじめての日 | 今日のデータがわずか、今週の過去データなし |

## 7. ステップ
各ステップの後、開発者が実機で確認してから次へ進む。

### step01: 土台
- プロジェクト構成（3章の画面すべてを中身が空の状態で作成）、Navigation、テーマ（色・文字サイズ・最大幅 480dp）、縦向き固定。
- 各画面にタイトルと「もどる」だけを置き、ホームから全画面に行き来できる。
- 完了条件: 実機でホーム → 各画面 → もどる が動く。

### step02: データの層とモック
- 4章のデータモデル、`ActivityRepository`、`FakeActivityRepository`（6章の全シナリオ）。
- 画面への組み込みはまだしない。シナリオごとの値を確かめる単体テストを書く。
- 完了条件: `./gradlew test` が通る。

### step03: ホーム
- 3.1 と 5章を実装。
- 完了条件: シナリオ（コード中で一時的に切り替え）ごとに、表示・メッセージ・停止時の表示が変わる。

### step04: ふりかえり
- 3.2 を実装（グラフは Canvas で自作）。
- 完了条件: きょう／今週 が切り替わり、特大の文字でも崩れない。

### step05: ビンゴ
- 3.3 を実装。
- 完了条件: マスの説明ダイアログ、1列そろったときの演出が動く。

### step06: せってい と スタッフ・開発用
- 3.4、3.5 を実装。文字サイズ・呼び名・目標を DataStore に保存。シナリオ切り替えを全画面に反映。
- 完了条件: 文字サイズを変えると全画面に反映され、アプリを再起動しても保持される。シナリオ切り替えがホームに即反映される。

### step07: 初回設定
- 3.6 を実装。
- 完了条件: 初回は初回設定が出て、完了後は出ない。スタッフ・開発用画面からやり直せる。

## 8. この段階で作らないもの
加速度の計測、フォアグラウンドサービス、活動の判別、Room、ファイル保存、Supabase、スタッフ向け Web 画面。
